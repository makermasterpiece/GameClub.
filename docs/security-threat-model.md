# GameClub Agent threat model

Scope: этапы 1–7 — enrollment, heartbeat, SignalR, allowlisted commands, визуальный Client Shell, player authentication, минимальный billing и Employee JWT/RBAC. Физическая защита станции, привилегированные Windows-команды, installer/update pipeline и полное production hardening находятся вне текущего этапа.

| Threat | Impact | Mitigation | Residual risk |
|---|---|---|---|
| Поддельный Agent | Ложный ONLINE, получение команд, подмена ACK | Одноразовый enrollment; уникальный 256-bit secret; HMAC каждого agent HTTP request; station identity берётся из проверенной подписи/JWT | Украденный активный credential позволяет имитацию до revoke |
| Украденный legacy `stationToken` | Доступ от имени станции через старую схему | Legacy endpoint включается только отдельным development-флагом; secure Agent его не использует; production default — off | Ошибочно включённый legacy-флаг в Development сохраняет старый риск |
| Replay attack | Повтор heartbeat/session request или повторное выполнение команды | Timestamp ±60 секунд; случайный nonce; атомарный in-memory nonce store с TTL 2 минуты; persistent command ID/nonce ledger минимум 24 часа | HTTP nonce store локален процессу и не разделяется между несколькими Server instances; нужен Redis на следующем этапе масштабирования |
| Man-in-the-middle | Чтение/изменение трафика, кража bearer JWT | HTTPS обязателен вне Development; certificate validation не отключается; HMAC защищает request integrity; ECDSA защищает команды независимо от транспорта | Компрометация доверенного CA/OS trust store остаётся риском |
| Подмена Server | Отправка Agent вредоносной/ложной команды | Agent pin-ит ECDSA P-256 public key при enrollment и проверяет каждую команду | Подмена Server именно во время первичного enrollment может подменить public key; enrollment проводится по доверенному TLS в контролируемой сети |
| Compromised operator account | Нежелательные операции со станциями, игроками и деньгами | Отдельная Employee JWT scheme, server-side policies и актуальная DB role/stamp; Operator не имеет security/adjustment/catalog прав; audit actor; allowlist | Компрометированный аккаунт сохраняет свои разрешённые действия до revoke; MFA и внешний identity provider не реализованы |
| Compromised station | Кража локального identity, ложные ACK, чтение TestMessage | DPAPI LocalMachine; ожидаемые ACL; уникальный credential на станцию; revoke/re-enroll | Local administrator/SYSTEM или процесс в контексте service способен использовать/извлечь credential; сервер не может сделать скомпрометированную станцию доверенной |
| Утечка логов | Раскрытие ключей/token/JWT/database password | Structured logging использует IDs/event type и безопасные причины; приложение не пишет secret/token/JWT/signature input | Browser SignalR использует query access_token только для Admin Hub: reverse proxy/APM должен скрывать этот параметр и Authorization; произвольное HTTP logging небезопасно |
| Изменение config Agent | Перенаправление Agent, downgrade на HTTP, подмена путей | HTTPS policy отказывает в запуске вне Development; HTTP требует одновременно Development + explicit opt-in; secret/public key хранятся в DPAPI credential file, не appsettings | Local administrator может заменить binary/config и отключить весь Agent; это endpoint compromise |
| Malicious command payload | DoS, инъекция или обход обработчика | Только `Ping`/`TestMessage`/`LockStation`/`UnlockStation`/`LogoutPlayer`; state/logout commands не имеют payload; неизвестные JSON-поля запрещены Agent; payload 16 KiB; generic execution отсутствует | Уязвимость в будущих обработчиках потребует отдельного threat review до расширения allowlist |
| Password disclosure | Credential theft через storage, DTO или logs | PasswordBox; bounded transient IPC/HTTPS request; Identity PBKDF2 hash; password/hash отсутствуют в state/results/logs | Same-user memory inspection находится вне process-level гарантий MVP |
| Username enumeration | Подбор существующих аккаунтов | Unknown user и wrong password дают одинаковый `INVALID_CREDENTIALS`; per-station rate limiting | Disabled/Banned codes намеренно различимы после корректного password согласно продуктовым требованиям |
| Concurrent duplicate login | Один User на нескольких PC или два User на одном PC | Service checks плюс два PostgreSQL partial unique index для `Active` | Необходим monitoring database constraint violations |
| Forged station identity during login | Session создаётся для чужой station | Login body не имеет stationId; identity выводится только из HMAC-authenticated request headers | Компрометация station credential требует revoke/re-enrollment |
| Stale local player snapshot | После restart Client показывает уже завершённую session | Agent показывает Offline до authenticated current-session reconciliation; Server является authority | При недоступном Server вход остаётся недоступен fail-closed |
| Локальная подмена IPC peer | Ложный ACK Client или показ поддельного состояния, когда Agent остановлен | Named Pipe вместо TCP; `FirstPipeInstance`; ACL для SYSTEM/Administrators/current identity/local Interactive SID; protocol не принимает state от Client | Все процессы одного interactive Windows identity имеют одинаковый SID. Проверка подписи конкретного Client binary/process owner остаётся будущим hardening-пунктом |
| Duplicate command delivery | Повтор side effect после reconnect/restart | Server command ID; SQLite unique `command_id` и `nonce`; состояние хранится 24 часа; duplicate только повторно сообщает итог | После retention повтор возможен, но server TTL команды 5 минут делает валидную повторную доставку после 24 часов невозможной |
| Clock skew | Отказ валидных запросов/команд или расширение replay window | HTTP окно ±60 секунд; command expiry и bounded creation time; UTC/Unix timestamps в canonical data | Сильно неверные часы вызывают отказ в обслуживании; станции и Server должны использовать NTP |
| Stolen Employee JWT / stale role | Чтение клубных данных или сохранение доступа после изменения роли | Audience/scheme separation; DB role/status/stamp при JWT validation; stamp rotation при access/password/logout; открытые employee hubs повторно проверяются примерно раз в 10 секунд | Bearer token можно использовать до отзыва/expiry; защита браузера и host остаётся необходимой; hub revoke не мгновенный |
| Billing replay/concurrent debit | Двойная оплата или расход одного баланса дважды | SERIALIZABLE use cases, уникальные operationId, проверка тела при повторе, reserve/charge/session/event в одной транзакции | Администратор БД может изменить ledger; это не tamper-proof финансовый журнал и не интеграция платёжного провайдера |
| Local timer/window manipulation | Игра после оплаченного срока или перенос ночного пакета паузой | Server-calculated time, display-only Stopwatch, persisted UTC hard window, auth TTL, fail-closed reconciliation | Client — визуальная оболочка: локальный администратор способен обходить UI; настоящий kiosk lockdown не реализован |
| Command tampering | Исполнение изменённого type/payload/station/expiry | ECDSA P-256/SHA-256 над versioned canonical representation и SHA-256 payload hash; `FixedTimeEquals` для HMAC | Компрометация server private key позволяет подписывать команды до замены ключа и re-enrollment |

## Assumptions

- Server host, Data Protection key ring и ECDSA private key административно защищены.
- PostgreSQL доступен только Server; DB operator считается частично доверенным: он видит metadata/hashes/ciphertext, но не plaintext station secret.
- Первичный enrollment выполняется оператором по доверенному HTTPS и короткоживущему каналу доставки token.
- Windows Service запускается в выделенном service account или SYSTEM, а `%ProgramData%\GameClub\Agent` имеет ограниченный ACL.
